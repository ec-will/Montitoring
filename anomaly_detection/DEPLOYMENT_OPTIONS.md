# Anomaly Detection Deployment Options

## Current Situation

**Data Flow:**
```
jeffsc8 (HPC Cluster)
  ├─ dashboard_cluster_usage.json (146K, updated hourly)
  ├─ dashboard_login_jobs.json (2.0M, updated every 5min)
  └─ Generated by cron jobs
       ↓
  NOT currently deployed to web servers
       ↓
  Only dashboard_data.json deployed (current status, not history)
```

**Web Servers:**
- rcity2.cottay.net:/srv/www/earthcast/
- ect-hpc.wx-farms.com
- Get HTML files with embedded data, not source JSON

---

## Option A: Separate Monitoring Instance (RECOMMENDED)

### Architecture
```
jeffsc8 (HPC)                  Monitoring Instance              Users
─────────────                  ───────────────────              ─────
Generate JSON files      SSH→   Fetch JSON files                Receive
every 5 minutes                 every 5 minutes                 ntfy alerts
                                    ↓
                                Run detector
                                    ↓
                                Detect anomalies
                                    ↓
                                Send ntfy alerts  ────────→      📱
```

### Implementation

**On jeffsc8:**
- Keep existing cron jobs (no changes)
- JSON files generated as usual
- Add deployment of JSON files to web servers (new)

**On monitoring instance** (new VM/container):
```bash
# Install
pip3 install numpy pyyaml requests

# Fetch data every 5 min (via SSH or HTTP)
*/5 * * * * /path/to/fetch_data.sh

# Run detector continuously
./job_detector.py --config config/detection_config_local.yaml

# Keepalive
*/5 * * * * /path/to/check_detector.sh
```

### Data Access Methods

#### Method 1: SSH Pull (Current)
```bash
# fetch_data.sh uses SSH
scp jeffsc8:/path/to/*.json ./data/
```
**Pros:** Already implemented, direct access  
**Cons:** Needs SSH access, can't detect jeffsc8 down vs network issue

#### Method 2: HTTP Pull (Better)
```bash
# Deploy JSON to web servers, fetch via HTTP
curl https://earthcast.wx-farms.com/dashboard_cluster_usage.json > data/
curl https://earthcast.wx-farms.com/dashboard_login_jobs.json > data/
```
**Pros:** Can detect jeffsc8 down (files stop updating), no SSH needed  
**Cons:** Requires updating deployment scripts on jeffsc8

#### Method 3: Push from jeffsc8 (Alternative)
```bash
# jeffsc8 pushes to monitoring instance
scp *.json monitoring-instance:/path/to/data/
```
**Pros:** Simpler network config  
**Cons:** Monitoring instance needs to accept incoming SSH

### PROS
✅ **Detects jeffsc8 down:** If JSON files stop updating, detector notices  
✅ **Multi-cluster ready:** Can monitor multiple clusters from one instance  
✅ **Independent monitoring:** Not affected by jeffsc8 load/restarts  
✅ **Centralized alerting:** Single point for all monitoring  
✅ **Easier testing:** Don't need HPC access to develop  
✅ **Better resource isolation:** Detector CPU/memory doesn't impact HPC  
✅ **Can run 24/7:** Even when cluster down for maintenance

### CONS
❌ **Additional infrastructure:** Need another server/VM/container  
❌ **Network dependency:** Requires reliable connectivity to jeffsc8  
❌ **Deployment complexity:** Need to deploy JSON files (if using HTTP)  
❌ **Latency:** 5-10 min delay between job run and detection  
❌ **More moving parts:** More places for failures

## Option B: Run on jeffsc8

### Architecture
```
jeffsc8 (HPC)                              Users
─────────────                              ─────
Generate JSON files                        Receive alerts
    ↓
Run detector locally
    ↓
Detect anomalies
    ↓
Send ntfy alerts  ─────────────────────→   📱
```

### Implementation
```bash
# On jeffsc8
cd /e/08/erthch01/monitoring/anomaly_detection

# Use local config (no fetching needed)
./job_detector.py --config config/detection_config.yaml

# Add to crontab
*/5 * * * * /path/to/check_detector.sh
```

### PROS
✅ **Simplest setup:** No additional servers needed  
✅ **Direct access:** Read JSON files directly, no network  
✅ **Fastest detection:** Instant access to new data  
✅ **No deployment changes:** Use existing files as-is  
✅ **Minimal latency:** Detects issues within 5 min

### CONS
❌ **Can't detect jeffsc8 down:** If cluster down, detector down too  
❌ **Single cluster only:** Would need separate instance per cluster  
❌ **HPC resource usage:** Uses login node resources  
❌ **Maintenance windows:** Detector offline during cluster maintenance  
❌ **Access required:** Need HPC login for debugging/changes

## Option C: Hybrid Approach

### Architecture
```
jeffsc8 (HPC)                  Monitoring Instance              Users
─────────────                  ───────────────────              ─────
Generate JSON ───deploy───→    Web Server (rcity2)              Alerts
Run detector (primary)           ↓
Send alerts  ────────────→    Backup detector       ─────→      📱
                              (if jeffsc8 silent)
```

**Primary:** Detector on jeffsc8 (fast)  
**Backup:** Detector on separate instance watching for staleness

### PROS
✅ **Best of both worlds:** Fast + resilient  
✅ **Detects jeffsc8 down:** Backup notices stale data  
✅ **Redundancy:** Two detection systems

### CONS
❌ **Most complex:** Two detectors to maintain  
❌ **Alert coordination:** Need to prevent duplicate alerts  
❌ **Higher cost:** Two systems running

---

## Recommendation: Option A (Separate Instance)

### Why?
1. **Your stated goal:** "Detect jeffsc8 being down" → needs external monitoring
2. **Future growth:** "Adding jobs from another cluster" → needs central instance
3. **Production reliability:** Independent monitoring is more robust
4. **Already designed for it:** Current implementation uses `fetch_data.sh`

### Minimal Changes Needed

#### 1. Update jeffsc8 deployment scripts
Add to `update_cluster_usage_cron.sh`:
```bash
# Deploy JSON files
scp dashboard_cluster_usage.json rcity2:/srv/www/earthcast/
scp dashboard_login_jobs.json rcity2:/srv/www/earthcast/
```

#### 2. Update fetch_data.sh for HTTP
```bash
# Change from SSH to HTTP
curl -s https://earthcast.wx-farms.com/dashboard_cluster_usage.json > data/
curl -s https://earthcast.wx-farms.com/dashboard_login_jobs.json > data/
```

#### 3. Deploy to monitoring instance
- Could be: Docker container, VM, or even your local Mac
- Run `job_detector.py` 24/7
- Alerts via ntfy to your phone

### Detecting jeffsc8 Down

The detector would notice:
```python
# Check file age
file_age = now - last_modified_time(json_file)
if file_age > 15 minutes:  # Should update every 5 min
    alert("jeffsc8 may be down - data is stale")

# Check job staleness
if all jobs last_seen > expected_intervals:
    alert("All jobs missing - cluster likely down")
```
