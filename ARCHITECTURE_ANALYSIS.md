## Production Data Pipeline

### 1. Cluster Usage (Hourly - cron: `0 * * * *`)
**Script**: `update_cluster_usage_cron.sh`
- Runs `dashboard_cluster_usage.py` 
  - Calls `/usr/login/bin/myusage --start now-48h --count 2000 --csv`
  - Generates `dashboard_cluster_usage.json` (146K)
- Runs `web_server_timeline_plot.py`
  - Converts JSON → `cluster_usage_timeline.html`
- Deploys HTML to:
  - rcity2.cottay.net:/srv/www/earthcast
  - ect-hpc.wx-farms.com:/srv/www/earthcast
- **JSON file NOT deployed** (stays on jeffsc8)

### 2. Login Jobs Timeline (Every 10 min - cron: `*/10 * * * *`)
**Script**: `deploy_login_timeline.sh`
- Reads existing `dashboard_login_jobs.json` (2.0M)
- Runs `web_server_login_timeline_plot.py`
  - Converts JSON → `login_jobs_timeline.html`
- Deploys HTML to web servers
- **JSON file NOT deployed** (stays on jeffsc8)

### 3. Login Jobs Tracker (Continuous daemon)
**Script**: `dashboard_login_jobs.py` (untracked file)
- Long-running daemon process (PID 383058, started Nov 15)
- Continuously monitors login node jobs
- Updates `dashboard_login_jobs.json` in real-time
- Started via `start_login_tracker.sh`

## Anomaly Detector Integration Path

### Current Situation
- Anomaly detector built on `anomaly-alerting` branch
- Branch based on older `web-dashboard` commit (be522dc)
- Detector expects JSON files that **do exist** on jeffsc8
- These JSON files are generated by scripts that **are committed** to web-dashboard

### Recommended Integration Approach

**Option 1: Merge web-dashboard → anomaly-alerting (Recommended)**
1. Pull latest `web-dashboard` from jeffsc8 to local
2. Merge `web-dashboard` → `anomaly-alerting` 
3. Resolve any conflicts
4. Deploy anomaly detector to jeffsc8 on updated branch

**Benefits**:
- Keeps all latest production features
- Anomaly detector uses actively maintained data pipeline
- Clean git history
- Can push back to jeffsc8 when ready

**Option 2: Deploy as Standalone (Alternative)**
1. Deploy anomaly detector directly on jeffsc8
2. Run independently of web-dashboard branch
3. Use existing JSON files as data source

**Benefits**:
- No git merge complexity
- Faster deployment
- Isolated from web-dashboard changes

**Drawbacks**:
- Code divergence
- Harder to maintain
- Not tracked in version control
